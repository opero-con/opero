# ADR-0017: Make v16 the main development line

- **Status:** Accepted; applied when the consolidation PR merges
- **Date:** 2026-11-04
- **Affects:** Integration branch, v15 maintenance source, production source transition
- **Supersedes:** ADR-0016's requirement to keep the v16 port separate from main

## Context

The live site runs v16, and the operator reports the v16 Opero branch is stable.
Keeping main on v15 makes new work target the wrong framework version and splits
ongoing development across two lines. Local v16 integration validation still has
gaps; observed production stability does not resolve them.

## Decision

- Consolidate the existing v16 compatibility, Desk navigation and capitalization
  naming commits into main through a reviewed PR. Main then targets v16 with
  the dependencies already declared by the compatibility work.
- Preserve the pre-consolidation main revision, dd11332, on maintenance/v15.
  Existing v15 installations must retain a v15-compatible source.
- New development targets main. The v15 maintenance branch is preserved rather
  than treated as a second default development branch.
- Keep the current fix/v16-compatibility production source until a separately
  approved Frappe Cloud source switch and deployment are verified. Delete that
  branch only after the source switch; merging alone does not authorize it.
- Preserve the documented validation gaps. This consolidation neither declares
  a full v16 test pass nor cuts a release or deploys to production.

## Consequences

- Pull requests no longer need a separate v16 target after consolidation.
- Main must not be installed or migrated on v15 benches.
- The Newsletter prerequisite and outstanding integration checks remain in force.
